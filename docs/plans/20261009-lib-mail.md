# v0.1.0: библиотека `github.com/lllypuk/mail`

## Overview

Волна 1 плана `docs/go-libs.md` (раздел `mail`). SMTP-отправитель написан трижды и копии разошлись:

| | DPP | fitness-app | family-money |
|---|---|---|---|
| файл | `internal/notify/smtp_mailer.go` | то же | то же |
| `Quit` после `DATA` | `:124` | `:100` | `:111` |
| срок сессии | `SendTimeout(size)`: 30 с + 1 с на 256 КБ | 30 с | только `ctx` (Sender даёт 15 с) |
| отмена `ctx` рвёт соединение | нет | нет | `context.AfterFunc` (`:83`) |
| `Letter` | + `Unsubscribe`, `ReplyTo`, `Attachments` | `To, Subject, Text` | `To, Subject, Text` |

Общий дефект: ошибка `QUIT` после принятого `DATA` возвращается из `Send` как отказ. У DPP и
fitness-app повтор river (`MaxAttempts = 5`, `identity/jobs.go:18` и `:17`) шлёт письмо второй раз;
DPP это сознательно терпит (`identity/jobs.go:123-125`), Sender family-money не повторяет, но
считает доставленное письмо `failed`.

Новый репозиторий по образцу `secret` и `codestyle`: stdlib only, CI GitHub Actions, общий
`.golangci.yml` без исключений. Результат — v0.1.0 с README и CHANGELOG. Подключение — три
отдельных плана в репозиториях потребителей (`docs/plans/20261009-mail-lib.md` в каждом): ralphex
работает в одном репозитории.

Не делаем: очередь и повторы (у потребителя), выбор `MAILER=log|smtp` и имена переменных
окружения (политика проекта), генерацию `Message-ID` (только передача от потребителя), HTML-письма,
пул соединений, DKIM.

## Решения (приняты 2026-10-09, не переигрывать)

1. **Основа — DPP** (`Letter` с вложениями, отпиской и `ReplyTo`, `Encode`, срок по размеру), отмена
   через `context.AfterFunc` и подмена корней TLS — из family-money.
2. **`TLSMode` явный**: `TLSStartTLS` (нулевое значение, безопасное умолчание) и `TLSImplicit`. Номер
   порта библиотека не толкует; «465 → implicit» остаётся в фасадах, чтобы env проектов не менялся.
3. **`Send(ctx, Letter) error`: `nil` тогда и только тогда, когда сервер принял `DATA`** (ответ 250
   на точку). Ошибка `QUIT` после этого не возвращается. Отказ — `*SendError{Phase, Outcome, Code,
   Err}`:
   - `Phase`: `dial | tls | auth | envelope | data`; рукопожатие implicit TLS внутри `DialContext` —
     `tls`, приветствие и EHLO (`NewClient`) — `dial`;
   - `Outcome`: `rejected` — письма у сервера нет (ответ 4xx/5xx, обрыв до конца тела);
     `unknown` — тело ушло, финального ответа нет (обрыв, срок, отмена после точки) — могло дойти;
   - в `data`: ошибка `Data()`/`Write` — `rejected`; ошибка `w.Close()` с `*textproto.Error` —
     `rejected` с `Code`, любая другая ошибка `Close` — `unknown`;
   - `Code` — код ответа SMTP из `*textproto.Error`, иначе 0; `Permanent()` — `Code >= 500`.
   Отмена и срок оборачиваются так, что `errors.Is(err, context.Canceled|DeadlineExceeded)` верен;
   дедлайн соединения (`os.ErrDeadlineExceeded`, может прийти раньше `ctx.Err()`) отображается в
   `context.DeadlineExceeded`. Ошибки `Validate` (`ErrInvalidAddress`, `ErrHeaderInjection`)
   возвращаются как есть, без `SendError`.
4. **Срок сессии**: `Config.SendTimeout` (0 — свой срок не ставится, только `ctx`) плюс
   `Config.SendRate` байт/с (0 — без роста). `Config.Timeout(size)` — функция конфига, а не
   отправителя: DPP считает срок джобы отзыва до сборки отправителя (`jobs_feedback.go:241`).
   `DialTimeout` 0 — 10 с.
5. **Адресат**: `Validate` разбирает `To` через `net/mail.ParseAddress`. В `RCPT TO` — голый адрес, в
   заголовке — `addr.String()` при имени, иначе голый адрес (без `<>`: заголовок простого адреса не
   меняется). Неразборчивый — `ErrInvalidAddress` до соединения. CR/LF в заголовочных полях и `"` в
   имени вложения — `ErrHeaderInjection`, как в DPP.
6. **`Letter.MessageID`** — необязательный; пусто — заголовка нет (как сейчас, ставит сервер).
   Значение с CR/LF или без `<…@…>` — `ErrHeaderInjection`/`ErrInvalidAddress`.
7. **Имена**: пакет `mail`, типы `Letter`, `Attachment{Name, MIME, Data}`, `SMTP`, `Log` — поля
   `Letter` совпадают с DPP, чтобы фасады были алиасами (`type Letter = mail.Letter`). Внутри
   библиотеки `net/mail` импортируется как `netmail`. Ошибки — `ErrInvalidFrom`, `ErrNoTLS`,
   `ErrHeaderInjection`, `ErrInvalidAddress`, `ErrConfig`.
8. **`Log`** пишет письмо целиком (`to`, `reply_to`, `subject`, `text`, вложения — имя и размер) на
   `Info` с сообщением `письмо не отправлено, режим разработки` (как в DPP); предупреждение о
   режиме при старте — у потребителя. `NewLog(nil)` не паникует при сборке
   (fitness-app собирает так в `cmd/worker/main_test.go`).
9. **Тестовый сервер** — `internal/smtptest` по образцу заглушки family-money
   (`internal/notify/smtp_mailer_test.go:197-331`), без testify; сертификат заглушки — через
   `Config.RootCAs`, а не `SSL_CERT_FILE` (DPP), поэтому тесты параллельные.
